# Plan — 07 Catalog import (text and photo)

## What we're building
An "Import" button on `/inventory/catalog` that opens a modal. The owner pastes text (a
supplier price list, an invoice, a WhatsApp message) or attaches one photo, plus the
supplier's lead time and email once for the whole import. A server action sends it to
DeepSeek with structured output and returns draft rows. The rows show in an editable table
in the same modal, where each can be kept or discarded and every field edited. Every row is
checked with 02's parsers, and the table says which rows join an existing product and which
SKUs clash. "Import N" writes the kept rows in one SQL statement. Nothing touches
`bran.products` or `bran.variants` before that click.

## Decisions
- **Server action, not a stream.** Extraction is one structured object the table needs
  whole, so there is nothing to show half-finished. `extractCatalog` in
  `src/actions/catalog-import.ts` calls `runAI` → `generateText({ output: Output.object })`.
  It follows the rules in `library-docs.md`: `runAI` logs the run, and `null` means "say
  it failed, keep the text so they can retry".
- **`runAI` gets an optional `timeoutMs`.** Its 15s default fits short explanations. A
  long price list may take longer, so import passes 60s. Other callers are unchanged.
- **The model returns only what the document says.** Every field is nullable, and the
  instructions say never to guess a price, a SKU or a count. Blank fields stay blank in the
  table and fail `parseVariant` until the owner fills them. Invented numbers in a catalogue
  would feed restock, which is worse than asking. Two defaults are the exception, and the
  table shows both: on-hand defaults to 0 (a price list doesn't tell you what's on the
  shelf), and minimum order defaults to 1 when the document doesn't give one.
- **Missing SKUs get a suggested one, generated by bran, not the model.** A pure function
  builds it from the product and variant (`LINEN-SHIRT-M`) and adds a `-2`, `-3` suffix to
  avoid existing and in-draft SKUs. The cell is marked "suggested" and can be edited.
  Without this, most price lists (which have no SKUs) would be a table full of red.
- **Lead time and supplier email are set once per import, not per row.** One import is
  normally one supplier's document. The two fields sit above the table and apply to every
  new product. If the document shows a supplier email, the model fills it in. The lead time
  starts at 21 days, the same default as 02's Add product dialog. Products that already
  exist keep their own values.
- **Existing products are matched by name, case-insensitively and ignoring extra spaces.**
  This is resolved on the server against `loadCatalog`, both when drafting (to label the
  row "adds to *Linen Shirt*") and again at import (the client's labels aren't trusted).
  Archived variants still count as taken SKUs, because the unique constraint is on
  `(workspace_id, sku)`.
- **The pure logic lives in one import-free module**, `src/lib/catalog-import.ts`: turning
  the model's rows into draft rows (null → "", suggested SKUs), name normalising, and
  per-row checks (parse errors, in-draft duplicate SKUs, clashes with existing SKUs). The
  dialog and `importCatalog` run the same function, and `node --test` tests it the way
  `catalog-input.test.ts` does.
- **One statement makes the import atomic.** The same approach as `createDraftOrder`: a
  CTE inserts the new products from `unnest(...)` arrays, returning their ids, then inserts
  every variant, taking its `product_id` from either the new product or the matched
  existing one. If any part fails, the whole statement rolls back, and nothing needs
  `sql.transaction`. A unique violation (a SKU taken between drafting and importing) is
  mapped back to the row, and nothing is written.
- **The photo goes through a separate `visionModel()` in `model.ts`**
  (`deepseek-v4-flash-vision-exp`), so no other file learns a provider id. The browser
  downsizes the image (longest side 1600px, JPEG) before sending it as a data URL. That
  keeps it well under the Server Action's 1 MB default body limit without changing
  `next.config.ts`. The image is never stored.
- **Vision gets tested first, before any UI.** Build step 2 is a script that sends one
  real photo of a price list to the vision model. If it fails or produces rubbish across a
  couple of photos, 07 ships text-only. The attach control is hidden and the dialog says
  "Photo import isn't available yet", and the decision goes in `log.md`, as the spec
  allows.
- **UI:** install AI Elements `attachments` (the CLI, answering "n" to overwrite
  prompts), restyle it onto tokens, and reuse the existing `prompt-input` for the text
  box. The modal loads with `next/dynamic` on first open, so the catalog page doesn't pay
  for AI Elements (the bundle lesson from 06). The draft table is a plain table inside the
  modal, one row per variant: keep toggle, product (+ "new" / "adds to" badge), variant,
  SKU, cost, price, on-hand, min order, each an inline input with its error below. It
  scrolls inside the modal; the page-level fixed-height/pager rules don't apply (spec).
- **Row cap: 100 draft rows.** The schema's array has `.max(100)`. A longer document is
  cut off, and the dialog says so and suggests splitting it. This keeps output tokens and
  the table sane.

## Assumptions
- `deepseek-v4-flash` with thinking off follows a nullable-field `Output.object` schema
  reliably on messy text. The first real call in step 2 checks this too.
- The DeepSeek provider accepts an image as a file part (`mediaType: image/jpeg`, data URL)
  on the vision model, per its docs. Not yet verified.
- A downsized 1600px JPEG of a price list is under ~600 KB, which fits the 1 MB action
  limit with the other fields.
- Neon's HTTP driver runs the multi-CTE insert as one implicit transaction. This holds for
  `createDraftOrder` today.
- Owners import tens of rows at a time, not thousands.

## How to build it
1. `runAI` gets an optional `timeoutMs`. `model.ts` exports `visionModel()`.
2. **Vision spike:** `scripts/try-vision.ts` sends a photo to `visionModel()` with the
   draft schema and prints the result. Run it on 2–3 real photos and record the verdict in
   `log.md`.
3. `src/lib/catalog-import.ts`: the draft schema (zod, shared with the model call),
   `toDraftRows`, `suggestSku`, `normaliseName`, `checkDraft(rows, existing)` → per-row
   errors and a "new / adds to" match. `catalog-import.test.ts` covers nulls, suggested SKU
   collisions (existing + in-draft + archived), name matching, parse errors, and the cap.
4. `src/lib/ai/catalog-extract.ts`: builds the prompt and calls `generateText` with
   `Output.object`. It takes a `LanguageModel` argument so tests can pass
   `MockLanguageModelV4`.
5. `src/actions/catalog-import.ts`:
   - `extractCatalog({ text?, image? })`: gets the session workspace, checks size (text ≤
     20k chars, image ≤ 900 KB data URL), runs `runAI` with feature `catalog-import`, then
     `checkDraft` against `loadCatalog`, and returns draft rows.
   - `importCatalog({ rows, leadTimeDays, supplierEmail })`: re-parses and re-checks every
     row on the server, writes them in one CTE statement scoped by `workspace_id`, then
     `revalidatePath` for catalog and inventory.
6. Install and restyle `attachments`. Build `CatalogImportDialog.tsx` in
   `src/components/bran/`: the input step (prompt-input + attachments + supplier fields),
   then the review step (the draft table and "Import N", disabled while any kept row has an
   error). Add the "Import" button to the `CatalogTable` header, next to "Add product", and
   load the dialog with `next/dynamic`. When there's no key or no session, show the message
   instead of the input.
7. Verify every "done when" in the browser, plus SQL row counts before and after a draft
   and after an import, and an `ai_runs` query. Log the evidence in `log.md`.
8. `pnpm check`, `pnpm test`. Update `library-docs.md` (vision verdict, the `attachments`
   install notes) and `ui-registry.md` (the draft table pattern).

## Out of scope
- Storing photos in R2; more than one image per import
- Updating existing variants (cost, price, stock) from an import
- Per-row supplier / lead time (set once per import; edit the product afterwards)
- .csv / .xlsx file parsing; paste the cells as text
- Importing the FLVS storefront's catalogue
